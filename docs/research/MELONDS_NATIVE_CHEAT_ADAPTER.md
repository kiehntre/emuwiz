# Native melonDS cheat adapter

## Source of truth

The adapter follows current melonDS source rather than a remembered or
third-party representation. `ARCodeFile` reads and writes a bounded text MCH
grammar containing `ROOT`, `CAT`, `CODE`, `DESC`, and pairs of eight-hex-digit
words. A CODE header carries its enabled flag; a category carries the native
`OnlyOneCodeEnabled` rule.

Primary references:

- [melonDS ARCodeFile.h](https://raw.githubusercontent.com/melonDS-emu/melonDS/master/src/ARCodeFile.h)
- [melonDS ARCodeFile.cpp](https://raw.githubusercontent.com/melonDS-emu/melonDS/master/src/ARCodeFile.cpp)
- [melonDS CheatsDialog.h](https://github.com/melonDS-emu/melonDS/blob/master/src/frontend/qt_sdl/CheatsDialog.h)
- [melonDS 1.1 release notes](https://github.com/melonDS-emu/melonDS/releases)

The upstream frontend constructs the cheat filename from the ROM asset path
and `.mch`; an optional configured cheat path can relocate that sibling file.
The adapter therefore accepts an explicit approved destination root and never
guesses a global database path.

## Parser and normalization

`melonds_cheat.rs` bounds bytes, lines, names, code count, and word pairs. It
retains comments, descriptions, categories, root codes, enabled state, and
unknown raw word pairs. Malformed directives, duplicate names, missing code
bodies, and out-of-scope data are reported as typed issues.

Each pair is passed to the existing DS Action Replay classifier. Proven direct
write operations are normalized into the existing EmuWiz Cheat IR; conditional,
pointer, loop, offset, master, and unknown operations remain opaque native
word pairs. DS Action Replay decoding is not duplicated here.

## Identity and database boundary

Apply/loadability requires a verified ROM identity: exact SHA-256 is preferred,
with a verified four-character DS game code as the fallback. A title hint is
display-only and cannot authorize unattended Apply. ROM bytes are never
modified.

`usrcheat.dat` is classified as `UserImportOnly`. EmuWiz does not download,
bundle, scrape, or modify that external database. Local import support can be
added by a separate approved source workflow.

## Merge, enablement, and transaction safety

The writer deterministically renders native MCH text, preserves unrelated
categories/codes and opaque operations, avoids ambiguous duplicate-name
merges, and supports removing one named code. Enable/disable changes the
native CODE flag and enforces melonDS's category-level single-enabled rule.

Generated bytes are reparsed before planning. The adapter then uses the shared
preview and transaction/history executor for source fingerprint checks,
destination safety, atomic publication, exact backup, verification, and
rollback. A rollback may remove a newly created file only while it still
matches the transaction-created bytes; externally changed destinations are
refused.

melonDS's global `EnableCheats` setting is exposed as a loadability fact but is
not modified by this adapter. A reload/restart is reported as required after a
native file/state change.

## GUI boundary and limitations

The shared preview labels melonDS as a distinct adapter and verified-ROM
identity, and the existing Cheats workflow receives adapter-specific wording.
Generic routing, compatibility analysis, provider infrastructure, and
database acquisition remain outside this feature.

The current adapter does not interpret every Action Replay operation. It
preserves unsupported operations exactly as native words and reports that
normalization is partial.
