# EmuWiz v0.8.1-alpha release notes

**Status: release candidate, not yet tagged or published.** The currently
published release remains [`v0.8.0-alpha`](v0.8.0-alpha.md). This document
describes what has merged to `main` toward `v0.8.1-alpha` and is kept up to
date as the candidate stabilizes; it will have its "not yet tagged" note
removed when the tag is cut.

EmuWiz v0.8.1-alpha ("Alpha 2.1") is an identity, launch, optical, and
whole-collection library release. It builds directly on the 0.8.0 Repair
Center and Library Views work: more platforms are identified from their own
on-disc evidence, more emulators have verified native launch or readiness
reporting, optical discs gain a representation-independent fingerprint and a
verified CUE/BIN -> CHD conversion, RomM-ready planning now spans a whole
multi-platform collection, and the DAT workflow gains collection-completion
reporting with managed snapshot revisions and local rollback. It ships no
new database schema and changes no existing DAT, identity, launch,
transaction, RomM, cheats, or mods semantics.

## Highlights

### Identity: more platforms verified from their own evidence

- **ScummVM game folders** are identified from their actual detection
  entries, not from a folder name.
- **3DO game discs** are identified from the Opera filesystem volume header
  (volume and root unique identifiers plus logical block geometry), exposed
  as a structured disc identity, never a database title lookup.
- **PC-FX game discs** are identified from the documented
  representation-independent PC-FX disc hash computed over the boot
  signature, volume header, and header-directed boot sectors.
- **Loose-ROM cartridge identity** for NES, Game Boy / Game Boy Color /
  Game Boy Advance, and N64 is verified from the cartridge headers.
- **Disc identity promoted into game reports** for PlayStation, Sega Saturn,
  Dreamcast, PSP, PS3, and original Xbox.

### Optical / disc

- **Canonical optical fingerprint.** A representation-independent
  fingerprint of an optical disc's actual data content, so the same disc as
  CUE/BIN and as CHD compares as equivalent.
- **Verified CUE/BIN -> CHD conversion.** Conversion only finalizes when the
  staged CHD independently reproduces the source's canonical optical
  fingerprint. It runs through the existing journalled transaction engine,
  so it has crash-safe recovery and full rollback, and it never deletes the
  original (an optional step moves the source to a reversible quarantine
  folder instead).
- **Disc conversion GUI.** A "Convert discs" workflow on Home to preview,
  apply, and undo a conversion.
- **Equivalent-representation review.** Review tooling for byte-different but
  content-equivalent CUE/BIN and CHD discs, and for equivalent N64 ROM
  representations, alongside the existing exact-duplicate quarantine.

### Launch / emulators

- **Verified native ScummVM launch execution.**
- **Verified command planning and/or readiness reporting** for PPSSPP,
  RPCS3, xemu, and Xenia, surfaced in the Doctor and Game Details readiness
  views. Unverified inputs fail closed rather than launching.
- **Unified launch planning and execution.** Compatibility rows, identity
  resolution, emulator/profile discovery, readiness, command planning, and
  process execution are separate stages. RetroArch core-database matching,
  reviewed single-entry core preferences, MAME shortname authority, PCSX2
  direct-content restrictions, and the launch-evidence bridge are current
  family-specific rules; coverage is not universal.
- **Additional current identity evidence.** PS2 ISO identity can be read
  through supported CHD routing; NGP/NGPC headers, Macintosh DC42 evidence,
  and specialist Dreamcast GD-ROM/CHD routing are represented explicitly.
  C64/tape ambiguity and Virtual Boy media recognition remain conservative:
  recognition is not silently promoted to verified game identity.

### DAT

- **Collection completion reporting.** The DAT Sources page shows how
  complete a catalogued collection is against its managed DATs.
- **Managed DAT snapshot provenance.** Managed DAT sources (MAME, Redump,
  TOSEC, browser-assisted No-Intro import) record which snapshot revision
  each catalogue came from and expose a "Revision history" view.
- **Local DAT revision rollback.** A managed DAT source can be rolled back
  to a previously imported local revision.
- **Bulk DAT source validation** surfaces unusable or misconfigured sources
  in one pass, failing closed on anything it cannot validate.
- **Persisted DAT and identity evidence.** Library DAT identities, disk-only
  CHD set results, set-audit verdicts, and verified identity facts are
  persisted with source and freshness provenance.

### Library / RomM

- **Whole-collection RomM-ready planning.** Plan a RomM layout across a
  whole multi-platform collection at once. The single-platform RomM
  projection, the Playing Library 1G1R election, and the multi-file /
  multi-disc companion handling are all reused unchanged. The combined plan
  adds read-only preview checks the single-platform path cannot perform:
  a missing source, an unsafe (symlinked) source, a destination already
  occupied on disk, and a destination that two platform inputs both claim.
  Each is reported and never auto-resolved, moved aside, or overwritten.
- Apply reuses the existing journalled, no-clobber symlink transaction
  engine, one transaction per platform.

### GUI / discoverability

- The Home screen has direct entry points for **Build RomM library**,
  **Convert discs**, **Find duplicate / equivalent games**, **Verify
  collection** (DATs), **Set up emulators**, and **Cheats & Mods**.
- The DAT Sources page surfaces **collection completion**, **revision
  history**, and **revision rollback** directly.

### Safety

- **Transactional safety audit.** The landed DAT-rename, Playing Library /
  RomM symlink, optical-conversion, and duplicate-quarantine apply/rollback
  paths were audited against TOCTOU, interrupted-apply, stale-journal, and
  rollback-refusal cases. No production safety regression was found; the
  existing fail-closed behaviour (no-clobber `renameat2`, double preflight,
  identity re-verification, ancestor-path confinement, honest crash
  reconciliation) is unchanged.
- **Cross-platform RomM destination-collision refusal is now proven** with
  regression tests: two per-platform RomM apply transactions targeting the
  same destination cannot overwrite each other or a user's originals - the
  second is refused by the shared engine's live filesystem check, in either
  hard-conflict mode and regardless of apply order.
- **Cheats & Mods transaction workflows.** Selected verified PCSX2, Dolphin,
  RetroArch, and GameCube/Wii provider records can use explicit confirmation,
  shared apply, journal/history, verification, and rollback where the
  adapter supplies a safe materialized source. Discovery, provider browsing,
  source validation, inventory, and preview remain read-only.
- **Safe local mod-package inspection.** Local packages can be inspected and
  planned conservatively; unsupported patch formats fail closed. Downloads
  and external installers are not part of the local Stage 1 workflow.
- **Doctor and front-door documentation refresh.** Diagnostics cover current
  environment, database, emulator/readiness, managed-path, and identity
  findings; the README, architecture references, launch support, and
  historical/superseded labels now point at current guidance.

### Under the hood

A large run of read-only identity, emulator-adapter, evidence-ingestion,
and launch-planning groundwork merged in this range: explainable platform
evidence fusion, normalized DAT matching and set identity, local emulator
adapters and BIOS verification for several systems, universal source
ingestion, reversible ROM header / SMD / N64 normalization *observation*
(no ROM is rewritten), and RAR5 audit integration.

## Known limitations

- 3DO and PC-FX identity is read from 2048-byte-sector ISO images and from
  MODE1/MODE2 2352 CUE/BIN only. 3DO and PC-FX identity from `.chd` is not
  yet supported and fails closed rather than guessing.
- CHD identity overall is still limited: PlayStation (pure-Rust track
  reader) and multi-track Dreamcast GD-ROM (only when the optional
  `chd-optical-specialist` build feature is enabled) are the supported
  cases; other platforms' CHDs are refused.
- Not every emulator or platform has verified native launch support. Some
  emulators expose readiness or command-planning only, and unverified
  inputs fail closed rather than launching.
- The whole-collection RomM planner produces the combined plan and the
  per-platform apply transactions, but is driven through the existing
  Playing Library / RomM GUI rather than a dedicated multi-platform wizard.
- Reversible ROM header / SMD / N64 normalization is observation only in
  this release; no ROM is rewritten.
- Exact resume and CheatBase Stage 1 are not part of this release. There is
  no universal mod installer, and Virtual Boy media recognition does not
  constitute verified identity or launch support.

## Install

```sh
VERSION=v0.8.1-alpha
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/archivefs-$VERSION-x86_64-linux.tar.gz
curl -LO https://github.com/kiehntre/emuwiz/releases/download/$VERSION/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf archivefs-$VERSION-x86_64-linux.tar.gz
cd archivefs-$VERSION-x86_64-linux
./emuwiz-cli --version
./install.sh
```

The installer remains per-user, uses no `sudo`, and preserves existing
configuration. Existing ArchiveFS package names, executable aliases, legacy
config/data paths, environment variables, database schema, rename journals,
and `archivefs-v*` artifact naming remain compatible. There is no schema or
migration change in this release.
