# Organisation / Playing Library — Sunshine review

Use a disposable library and output folder. Never use live games for apply checks.
This checklist is prepared for a manual Sunshine session; it has not been run.
Do not launch DISPLAY=:0 as part of automated validation.

The promoted History & Undo Sunshine checklist remains outstanding as a release
acceptance requirement: `docs/architecture/GUI_V2_HISTORY_UNDO_LIVE_CHECKLIST.md`.
Automated Organisation integration does not satisfy either manual checklist.

- Clean verified collection: Organisation has one primary Playing Library action,
  with Duplicates, Collection Review and canonical MAME handoffs.
- Playing Library: choose verification data, source and separate destination.
  Preview shows selected releases before Apply, linked output and originals preserved.
- Mixed regions: preference reason comes from the planner and is visible normally;
  alternatives retain their rejection reasons.
- Uncertain identity: filename-only or unmatched files say Needs review; tied
  verified releases are not silently elected. Review counts include groups and files.
- Duplicate group: preferred copy and reason are visible before Preview. Preview,
  confirmation and the existing quarantine executor remain distinct steps.
  Quarantine retains bytes and must never claim that disk space was freed.
- No duplicates: canonical duplicate review shows its specific no-duplicates state;
  equivalent-format scans show no equivalent copies and the number examined.
- Conflicts: filter shows conflicts; Apply is unavailable and no force control exists.
- MAME title: Open MAME enters the existing MAME surface; set organisation stays
  in that workflow and does not offer generic Playing Library output from it.
- Destination conflict: existing backend refusal is shown with details; originals
  and conflicting output stay unchanged. No overwrite bypass is offered.
- Preview-only: without a ready output profile, explanation is visible and no
  invented Apply is offered. RomM/RetroDECK retain their visibility checks.
- Empty library: distinguish no source files from no verified eligible games;
  already-correct owned output has its own up-to-date message.
- Filtered empty: Needs review / Excluded can say filters hide all results;
  Conflicts says no conflicts when appropriate. Counts remain whole-preview totals.
- Advanced: expand Technical details for DAT entry, family, evidence, alternatives,
  source/output paths and conflict provenance. Prior receipts are labelled historical.
- Narrow 1024×600: wrapped actions and labels stay usable; scroll the preview,
  check destination and confirm controls. Check bounded review pages on a large
  fixture; the next page must expose later games without changing the totals.

No new detector, planner, ranking, writer, merge, automatic delete or history engine
is introduced. Review observations are the existing matcher's candidates absent
from its matches/rejected launchers, excluding accepted companions. They do not
claim a specific reason (ambiguous, unreadable, absent or unmatched checksum).
