# Blue automatic Discovery import integration

Integration base: promoted managed-DAT / verification-guidance main `007139a7affb21df1f718cd526488d4956befbca`. Existing automatic Discovery candidate: `1b3d82716b9ec9de4e17a3efff02cd65eb032c18`, reconciled without dropping concurrent main changes. Game Verification Guidance implementation `3592674a` is already included in that base.

An ordinary user opens Sources, adds an existing games folder, then uses Discovery. Adding a source uses the existing explicit configuration/database registration and selects that folder in Discovery; it does not scan/import files. A new folder's storage binding is reviewed and confirmed through the existing source-health dialog. Discovery remains read-only and automatically prepares the first safe batch on a worker. The user reviews its exact allowlist, acknowledges the selective-Undo conditions, then confirms Apply. Each further batch is prepared automatically but requires its own confirmation. Manual subset controls remain available as an advanced path.

Batches retain the existing native limit of 100 candidates and the existing input/decode/reference budgets. Discovery comparison retains its shared limit of 32 catalogue inputs, 32 MiB per catalogue and 128 MiB aggregate catalogue input. Exclusions, incomplete relationship checks, deferred oversized candidates, partial coverage and per-path refusal reasons remain visible. No arbitrary caller path becomes an allowlist item. Changes to the selected folder, source configuration, database or generation revoke the pending review. Apply uses existing native revalidation, cancellation and atomic History receipts; selective Undo retains dependency and exact-record refusal checks and never deletes media files.

Resume uses fresh Discovery over the same folder. Durable committed records are excluded by the existing duplicate checks, even if the UI lost feedback from the previous worker. A queued, prepared or submitted batch is not labelled committed. Cancelled/refused work needs fresh preparation.

The final wiring consumes Discovery's existing route request at the Sources page boundary. “Verify <platform>…” opens the native `Route::PlatformCheck` for that exact canonical platform. Importing never marks a game Verified. The existing compatible-catalogue picker, native audit Preview/Confirm, audit-bound evidence persistence, unsupported-file exclusions and freshness guidance remain authoritative.

A dedicated source’s canonical saved system assignment narrows catalogue inputs before charging the shared limits; it never classifies media or overrides a configured child source. Mixed/unassigned roots retain the explicit all-platform resource refusal rather than silently dropping catalogues.

Discovery's local-catalogue loader is retained. A focused managed comparison adapter now enumerates installed managed game catalogues, filters known compatible platforms and enabled descriptor policy, then calls the promoted typed catalogue resolver. It does not implement its own DAT identity, snapshot trust, persistence or verification logic. Existing Discovery input guards bind the descriptor configuration before loading it, the typed managed state path and the exact backing object through later preparation/Apply. A policy/configuration change during loading or resolution refuses comparison. Missing local configuration permits managed-only comparison; malformed existing configuration fails closed. Missing, disabled, stale, tampered, incompatible and BIOS catalogues cannot supply managed game comparison evidence.

Selected Evidence's separately owned integration is untouched. Validation uses synthetic media and disposable databases/application roots, including first-folder registration/binding, automatic batches and exclusions, explicit confirmation/cancellation, changed-source/file refusal, resume without replay, History/Undo and platform navigation. Prior module review and 172 focused checks are existing evidence; this finish runs focused combined integration checks and obtains a new exact-commit independent review. No production imports, bulk audits or running-GUI replacement are involved.
